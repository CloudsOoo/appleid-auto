## 6. 任务调度流程

```
                ┌─────────────────────────────────┐
                │     Celery Beat (定时任务)      │
                │  每小时触发账号检测任务          │
                └──────────────┬──────────────────┘
                               │
                               ▼
                ┌─────────────────────────────────┐
                │  查询所有需要检测的账号          │
                │  WHERE auto_unlock = true        │
                │  AND next_check_at <= NOW()      │
                └──────────────┬──────────────────┘
                               │
                               ▼
                ┌─────────────────────────────────┐
                │  为每个账号创建 Celery Task     │
                │  根据优先级和权限分配           │
                └──────────────┬──────────────────┘
                               │
                ┌──────────────┴──────────────┐
                │                             │
                ▼                             ▼
    ┌────────────────────┐       ┌────────────────────┐
    │ Celery Worker 1    │       │ Celery Worker 2    │
    │ 获取任务           │       │ 获取任务           │
    └──────────┬─────────┘       └──────────┬─────────┘
               │                             │
               ▼                             ▼
    ┌────────────────────┐       ┌────────────────────┐
    │ 选择最优节点       │       │ 选择最优节点       │
    │ (负载最低的在线节点)│       │                    │
    └──────────┬─────────┘       └──────────┬─────────┘
               │                             │
               ▼                             ▼
    ┌────────────────────┐       ┌────────────────────┐
    │ 获取可用代理       │       │ 获取可用代理       │
    │ (成功率最高)       │       │                    │
    └──────────┬─────────┘       └──────────┬─────────┘
               │                             │
               ▼                             ▼
    ┌────────────────────┐       ┌────────────────────┐
    │ 执行任务           │       │ 执行任务           │
    └──────────┬─────────┘       └──────────┬─────────┘
               │                             │
               │          ┌──────────────────┴────────┐
               │          │                           │
               │      任务成功                    任务失败

               │  ┌───────────────┐         ┌─────────────────┐

               │  │记录成功日志   │                 │
               │  └───────────────┘      ┌──────────┴──────────┐
               │                         │                     │

               │                         │                     │

               │                │(延迟执行)       │   │记录错误日志     │
               │                └─────────────────┘   │通知管理员       │
               │                                      └─────────────────┘

               └─────────────────────────┐
```

## 总结

以上流程图和架构图展示了 Apple ID 自动解锁系统的完整业务流程和技术架构。

### 关键特点：

1. **分层架构** - 清晰的前后端分离，职责明确

3. **高可用** - 节点集群、代理池、负载均衡
4. **安全可靠** - 多层验证、HTML 过滤、加密存储
5. **可扩展** - 模块化设计，易于扩展新功能
